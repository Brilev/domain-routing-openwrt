# domain-routing-openwrt: OWRT 25.12.1 + AmneziaWG 2.0 adaptation

Этот набор файлов подготовлен как стартовая ветка для доработки репозитория `Brilev/domain-routing-openwrt` под OpenWrt 25.12.1.

## Что изменено

- добавлена поддержка нового пакетного менеджера `apk` для OpenWrt 25.12.x;
- сохранена обратная совместимость с `opkg` для 23.05 / 24.10;
- обновлена логика установки пакетов AmneziaWG с учетом релизов `awg-openwrt` для 25.12.1;
- добавлена поддержка параметров AmneziaWG 2.0:
  - `S3`, `S4`
  - `I1`–`I5`
- для AWG peer добавлен `::/0` рядом с `0.0.0.0/0`;
- в init-скрипт `getdomains` добавлено подключение пользовательского файла:
  - `/etc/domain-routing/custom-subdomains.lst`
- при первом запуске создается шаблон этого файла.

## Какой файл основной

Основной файл для замены в репозитории:

- `getdomains-install.sh`

## Дополнительные файлы

- `domain-routing-openwrt-owrt2512.patch` — unified diff относительно текущего `getdomains-install.sh`
- `README-OWRT-25.12.1.md` — эти заметки

## Формат custom-subdomains.lst

По одной строке на правило, например:

```text
nftset=/sub.example.com/4#inet#fw4#vpn_domains
nftset=/api.example.org/4#inet#fw4#vpn_domains
```

## Что я бы проверил на роутере отдельно

1. Установка `dnsmasq-full` именно на вашей сборке 25.12.1, так как вокруг `apk` в первые дни релиза уже есть багрепорты.
2. Что пакет `luci-proto-amneziawg` из релиза `awg-openwrt` для вашей платформы ставится без ручных зависимостей.
3. Что ваши параметры AWG 2.0 действительно совпадают с теми, которые экспортирует клиент AmneziaVPN 4.8.12.9+.
4. Что кастомный файл `/etc/domain-routing/custom-subdomains.lst` не ломает `dnsmasq --test`.

## Важная оговорка

Я не запускал этот скрипт на живом роутере с OWRT 25.12.1 в этой среде, поэтому это подготовленный патч/скрипт для вашей ветки, а не подтвержденный runtime-тестом релиз.
